2026-10-04 用户将原先讨论的三端同步范围收窄为 Mac 与 Windows，手机端不纳入此次开发；采用 Supabase，同一账号登录后自动同步。实现边界见 [ADR-0009](../decisions/0009-optional-desktop-sync.md)，部署前置条件见 [Supabase 配置说明](../engineering/SUPABASE_SETUP.md)。本节不表示现有安装包具备同步能力。

- 同步任务名称、备注、重要程度、DDL、完成/撤销、回收站/恢复、按日期保存的今日安排，以及今日、全部任务、截止日期的手动顺序；沿用同一个 Task ID。
- 本地 SQLite 继续作为日常读写入口，断网时可查看和修改，联网后补传；同步失败显示状态并可重试，不影响已经成功保存的本地任务。
- 窗口位置、屏幕、尺寸、展开模式、置顶、主题和 DDL 展示模式等本机偏好各自保留；未保存草稿不参与同步。
- 首次连接时须处理两台设备已有数据；同时离线修改同一任务、移出今日、删除/恢复和排序冲突时不能静默用整份旧快照覆盖另一端，也不能因重试创建重复任务或复活已删除任务。
- 同步为可选能力，未启用时继续使用现有本地模式。控制台填写托管 Supabase 项目 HTTPS 地址、公开 Publishable/anon key 和邮箱密码，并明确确认“将本机任务与此账号合并”；普通设置保存不能隐式启用同步。
- 云端以账号隔离文档并比较版本提交；客户端依据上次同步基线、本机和云端进行三方合并。不冲突的内容自动合并，冲突逐项呈现双方值、要求全部明确选择后确认，不能默认偏向一端。
- 密码不持久保存，登录令牌由系统凭据库保管，不进入 WebView、SQLite 或便携备份。项目绑定和无令牌的同步基线保存在本机；断开保留任务和云端内容，凭据失效可重新登录原账号，更换账号须先断开。
- 整份任务备份预览与恢复在同步仍绑定时拒绝，需先断开；恢复后重连会合并而非强行覆盖云端。便携备份仍为 v3，不携带同步身份、基线或凭据。同步不等于历史备份。
- 验收包含 Mac ↔ Windows 双向修改、断网后重连、重试幂等、并发冲突、删除/恢复、计划和三份顺序、跨时区 DDL、首次连接已有数据，以及各设备设置不被覆盖。

新建或实际修改 DDL 时固定来源 IANA 时区；精确时刻固定 UTC 瞬间，歧义或不存在的当地时刻拒绝并保留草稿。旧无时区 DDL 不自动猜测，普通标题/备注编辑不改变截止语义。退出前统一处理小窗、任务详情、新建与设置草稿；保存失败不退出。

小窗“今日计划”旁的＋可直接输入并添加今日任务，无需打开大窗；保存失败、输入法及未保存草稿保护是该入口的必要支持。

展开方式有两种模式，默认“单击展开、点击外部收起”；“悬停展开”由使用者主动选择，展开/收起延迟只在该模式显示。旧偏好缺少该字段时同样默认单击。

## 问题与目标

学习时，为了看今日任务而打开其他应用、手机或聊天页面，会打断正在做的事。产品应让用户在当前桌面内完成「看还有什么 → 勾选做完 → 回到学习」。

形态为一个桌面 App，提供大窗口控制台与边缘小窗，并通过菜单栏 / 系统托盘常驻。大窗负责集中管理，小窗负责学习时随时查看和完成任务。两者共享任务与设置，不是两个独立应用。

成功标准：看清任务无需切换应用；完成任务最多一次点击；查看不抢焦点；关闭不挡住其他程序；重启后任务不丢。具体性能先测基线，不在实现前声称达标。

## 两种界面的职责

| 界面 | 用户主要在这里做什么 | 界面边界 |
| --- | --- | --- |
| 边缘小窗 | 看今日任务与 DDL、拖动整理这两份列表、勾选/撤销、加入或移出今日、快速新建 | 保持紧凑；完整编辑与全局设置可跳转控制台 |
| 大窗口控制台 | 集中管理全部任务、今日安排、DDL、已完成；编辑任务与设置 | 正常系统窗口，不随鼠标离开消失，不强制置顶 |

控制台使用左侧导航、中央任务列表、右侧可收起的任务详情；设置作为控制台中的页面。导航为「今日、全部任务、截止日期、已完成」，侧栏底部提供「回收站、打开边缘小窗、设置」。无 DDL 且不在今日的未完成任务能在「全部任务」找到；已完成任务在「已完成」，删除任务在「回收站」。不加入项目树、看板、统计仪表盘或拆解入口。

小窗中的「管理任务」打开控制台；「设置」直接打开对应设置页；「完整编辑」按 Task ID 定位任务。菜单栏/托盘也可打开控制台或设置。重复操作复用同一个控制台，不不断开新窗口。

今日计划标题旁提供「＋」，可在小窗直接输入并添加今日任务，不打开控制台。快速输入只要求任务名称，默认普通优先级、无DDL；创建Task与今日计划在同一事务提交，成功后可连续添加。输入期间暂停自动收起，中文候选确认不得误提交；保存失败保留草稿，明确关闭或退出时处理未保存文字。完整编辑仍从任务详情进入控制台。

关闭控制台只关闭/隐藏这个大窗口，边缘小窗仍可使用；只有明确选择「退出 SideTask」才结束整个应用。控制台打开时是用户主动操作，可以获得焦点；边缘悬停仍不得抢走其他应用焦点。控制台前台编辑期间暂停非固定小窗的自动呼出，固定小窗可保留查看/勾选；未保存编辑不得被窗口切换丢弃。

完整控制台与边缘小窗是两个面向用户的界面；实现上可另有一个只负责触发的窄把手窗口，不新增第三套任务界面。

控制台恢复上次普通尺寸/位置和最大化偏好，小窗今日/DDL分区比例在操作结束后保留。设备偏好不改Task/Plan、不随任务备份覆盖；断屏或缩放变化时保留可操作的关闭/拖动入口，恢复不应自行激活其他窗口。保存失败必须可见并可重试或放弃本次位置，不影响任务编辑。首次常驻/恢复说明接入内联提示和设置常设帮助，确认状态独立于任务、成功才隐藏，不挡编辑或强制选屏。

## 界面风格

当前四套为纸笺（默认）、霜序（暖石灰/炭黑/酒红）、暖刊、极简。它们共享信息架构和任务行为，差异体现在色彩、标题字体、密度、边界和控件形态；不为某套风格增加独立任务库或额外功能。每套均支持浅色、深色和跟随系统。风格卡片即选即存；其他窗口设置仍显式保存，切换风格不能覆盖未保存的设置草稿。

旧版本没有 `uiStyle` 时默认纸笺，保留全部任务、计划和其他偏好。保存失败保留原风格并提示重试，不显示虚假成功。当前样式见[样式源码](../../apps/desktop/src/styles)，历史设计规范在本地保留。

## 小窗移动与防溢出

小窗的停靠位置可以调整，不锁在一个屏幕坐标。已确认支持沿屏幕边缘拖动；具体交互建议如下：

- 收起时拖边缘把手，展开时拖标题空白区，调整沿边位置；不从任务文字或勾选控件开始移动。
- 可拖到另一停靠边，或主动拖到另一显示器；松手后吸附到该屏幕最近的合法停靠边。当前左右边是初始布局方案，顶/底边是否加入另行评估。
- 主动按住拖动时可以经过屏幕接缝；松手后按目标屏幕工作区和缩放重新校准，再恢复自动呼出/收起。
- 「防溢出」约束的是停靠后的普通显示和展开/收起动画，不禁止用户主动移动窗口。仅鼠标经过另一屏幕，不会自动迁移小窗。
- 「固定展开」只暂停自动收起，不锁位置，固定后仍可拖动。
- 保存最近停靠的屏幕、边缘、沿边位置与尺寸，重启后恢复；屏幕断开时回退到可用屏幕。

## 任务语义：最重要的约定

例：「9 月 30 日交论文」设置 DDL 为 9 月 30 日；9 月 24 日选择「加入今日」。上下两处引用同一条任务，在今日勾选，就表示整项「交论文」已完成，DDL 区同步完成。

首版的每条任务都是一个独立的大任务，只有「未完成/已完成」两个完成状态。回收站标记与完成状态独立：取消任务可以移入回收站，无需将它标成完成，也不新增“已取消”业务状态。没有小任务拆解、嵌套清单、`parent_id`、部分完成百分比或父子自动完成。

「加入今日」表示今天准备处理这整项任务，不创建一个当日子任务。今天仅推进了一部分时，保持未完成；不能勾选后把它理解为只完成了当天的一小步。备注用于补充说明，不提供可勾选子项。

- `加入今日`：创建计划引用；不改 DDL，不克隆任务。同一天重复加入无效果。
- `移出今日`：只移除当天安排，原任务与 DDL 保留。如果仍有历史计划且未完成，会返回「此前未完成」待安排组；移出今日不表示今天彻底隐藏该任务。
- `整理列表顺序`：控制台的今日计划、全部任务、截止日期均可从行内排序把手拖动；小窗今日和截止日期提供相同入口。三份顺序互相独立，同一列表在大小窗同步。今日仍只调整当天未删除且未完成计划的顺序，控制台保留上移/下移按钮；不改变任务内容、DDL、完成记录、任务修订号或其他日期的安排。聚焦排序把手可用 `Alt+↑/↓` 移动，拖动时 `Esc` 取消。
- `保存顺序`：拖动只预览插入位置，松手后一次提交完整的当前可排序集合；搜索结果、已完成和回收站不提供局部重排。拖动期间若列表或快照版本改变，取消本次排序并提示重试；失败保留已提交顺序。全部任务与 DDL 已记录的隐藏任务位置保留，恢复后按原有槽位出现；未记录的新任务追加在已手动排序项目之后。今日新增或重新加入仍放到当天清单末尾。
- `完成/撤销完成`：只改任务主状态，所有视图一起更新。
- `移入回收站`：只设置删除时间；从今日、全部任务、DDL、已完成、正常搜索和相应计数中移除，原 Task ID、内容、DDL、完成时间和所有日期的计划仍保留。
- `恢复任务`：清除删除标记，保留原完成状态与全部计划。原来已完成的任务恢复后仍已完成；跨天不自动安排到今天，不改 DDL。回收站中的任务恢复前不能编辑、完成或增删计划。
- `已完成`：今日内默认进入折叠区，可撤销；记录不因跨天自动清空。今日已完成区只显示当日安排的任务，其余仍可从已完成页或正常全局搜索查询。
- 未指定重要程度默认为「普通」；可选「高、普通、低」。MVP 自定义的是每项任务的重要程度，不是自定义一套权重算法。

## 回收站的操作边界

回收站提供独立导航、数量、标题/备注搜索及单项恢复；正常全局搜索排除回收站。详情内区分“移入回收站”和“移出今日”。有草稿时提供继续编辑、保存后移入、放弃修改并移入；跨窗口删除不能关闭脏详情或丢掉输入，恢复后再明确处理冲突。任何恢复入口及“查看任务”导航都须遵守同样的草稿保护。具体焦点、失败反馈与恢复去向见 [UX](UX.md)。

第一阶段不提供永久删除、清空回收站、到期自动清理、批量生命周期或取消原因。便携备份包含回收站和全部计划，整份恢复会替换当前任务集合；它与恢复单项任务是不同操作。

## 每日计划与跨天

「每天的任务」在 MVP 中指每天安排的一次性任务，不等于重复习惯。

当天按系统本地日期展示。跨到新的一天不自动复制、不自动完成、不改截止日。最近一次安排在过去且仍未完成、也未安排今天的任务，显示在今日区内可折叠的「此前未完成」组，可逐个或批量转入今日。每个 Task 仅显示一次。

保留历史安排，未来如做统计需单独引入事件记录；不能把任务现在的状态当成过去某天的完成快照。睡眠唤醒、时区或系统日期变化时重新计算今日和逾期。

## DDL 区

- 下半部分显示所有未删除且有 DDL 的未完成任务，包括已经加入今日的任务，后者标记「已在今日」。重复的是展示位置，不是数据。
- 默认日期模式按有效截止时刻升序，并显示逾期/今天/以后的分组或标签，过期项自然在前。仅日期任务的显示标签使用所选日历日期，不能用排序用的次日零点显示成「次日截止」。
- 重要程度模式按高→普通→低分组，同级再按截止时刻升序；日期和逾期用文字/图标提示，不继续用日期分组盖过用户选择的优先级规则。
- 日期/重要程度模式完全相同的排序键，用创建时间、ID 保持稳定。手动模式按保存的顺序显示，逾期标签照常计算，不因日期或重要程度重新分组。未有手动顺序时沿用日期顺序；未记录的截止任务放到已有手动顺序之后，彼此仍按日期排序。
- 任一模式直接拖动 DDL 都在同一次保存中切为手动；切回日期/重要程度不会删除已保存顺序，再选手动即可恢复。今日和全部任务各自的顺序不随 DDL 排序变化，拖动不改变任何截止日期、时间或时区。
- 仅日期的 DDL 到所选日期结束后才算逾期；精确时刻在该时刻起逾期。内部规则见数据模型。
- DDL 是截止时间，不等于提醒。首版不主动发送提醒；可选提醒放到后续迭代。

## 明确延后

首版不包含：小任务拆解、父子任务、任务树、依赖关系与部分进度聚合。以后是否做需要新的需求决定，不预先搭建相关框架。

Mac 与 Windows 可选同步进入上述后续阶段，启用时使用同一 Supabase 邮箱账号；本地模式无需账号。手机端、外部任务平台双向同步、AI 自动规划、重复任务、番茄钟、日历聚合、团队协作、排行榜继续延后。不能在边缘小窗引入信息流或推广内容。

## 候选默认值（需实测）

| 项目 | 初值 |
| --- | --- |
| 位置 | 主屏右侧，上半段，可拖动把手沿边缘调整 |
| 展开等待 | 180 ms，可调 |
| 离开后收起等待 | 450 ms，可调 |
| 面板宽 × 高 | 360 × 560 逻辑单位，按工作区钳制 |
| 一般最小宽 × 高 | 280 × 320；工作区更小时工作区约束优先 |
| 外边距 | 8 逻辑单位；保留原生阴影时把阴影范围算入 |
| 多屏模式 | 一个面板记住最近停靠位置；可主动拖动重新停靠，也可在设置中选择位置；不自动跟随鼠标换屏 |
| 常驻入口 | 菜单栏 / 系统托盘，把手不闪烁 |
| 控制台布局 | 左侧导航＋任务列表＋可收起的详情栏；设置为独立页面 |
| 控制台启动策略 | 用户主动启动/再次打开应用时展示控制台 |

一个小窗可以在边缘调整位置，不能把“当前停靠屏幕”理解成永久绑定。每屏同时一个把手、自动跟随鼠标、顶边/底边停靠是可另行评估的选项。允许停靠在两屏接缝，展开和收起向停靠屏幕内部进行。

边缘小窗在主动拖动结束后恢复防溢出约束；控制台遵循普通窗口习惯，可拖动到其他屏幕或横跨屏幕，恢复时保证可见。主窗口名称、尺寸和导航均可通过原型调整。
